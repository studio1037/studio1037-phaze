# PHAZE v0.2 · облачный предпросмотр

В v0.2 добавлено раздельное пробуждение по будням и выходным с настраиваемыми днями недели. Начальные времена совпадают с прежним временем пользователя. События по часам сохраняют локальное время и исходную календарную дату запуска, относительные события сдвигаются вместе с пробуждением.

Google Calendar запрашивает только `calendar.readonly`. Данные из Google, его локальный кэш и OAuth-параметры остаются вне синхронизации PHAZE.

## Технический выбор

Supabase Auth и PostgreSQL с RLS позволяют ограничить доступ своим планом и сравнивать ревизии при записи. Клиент продолжает хранить план локально и при возвращении сети объединяет изменения с последней общей версией. При несовместимых правках пользователь выбирает сторону для конфликтующих записей и может скачать обе копии. Независимые события объединяются. Встроенный офлайн-режим Firestore тоже подходит для очереди, но для изменений одного документа использует последнюю запись. Поэтому для текущего требования к конфликтам выбраны явные ревизии и слияние.

## Развёртывание

1. Создай проект Supabase владельца PHAZE и выполни `supabase.sql` в SQL Editor.
2. Включи Email Auth и настрой письмо Magic Link с кодом `{{ .Token }}`. Для отправки писем внешним пользователям настрой собственный SMTP в Supabase.
3. В `sync-config.js` тестового развёртывания укажи публичный URL вида `https://PROJECT.supabase.co` и **publishable key**. Ключи `service_role` и secret key приложению не нужны.
4. На двух тестовых устройствах войди в один аккаунт. Проверь первичную загрузку плана, независимые правки офлайн, конфликт редактирования и удаления, смену расписания, выход и повторный вход. Третий браузер с другим аккаунтом должен видеть только свой план. На iPhone дополнительно проверь холодный офлайн-запуск и восстановление связи.

Ветка `v0.2` — предварительная сборка. Без подключения Supabase локальные функции работают, авторизация и обмен данными отключены. Синхронизация охватывает свои события, категории событий, правила повторения, отметки выполнения и расписание пробуждения. Синхронизация запускается при возвращении сети, открытии приложения и каждые 30 секунд в активной вкладке. Локальный JSON-экспорт доступен независимо от облака.

## Среды и выпуск

- Production v0.1.2: https://studio1037.github.io/studio1037-phaze/ — GitHub Pages из `main`.
- DEV v0.2: https://studio1037-phaze-dev.andypeshkov.chatgpt.site — отдельный origin с доступом владельца. Хостинг получает снимок файлов из ветки `v0.2`; после изменений нужно обновить опубликованный Site, постоянный URL сохраняется.
- После применения схемы запусти `supabase-rls-check.sql` в SQL Editor. Тестовые записи откатываются в конце транзакции. Проверь вход и синхронизацию на двух браузерах с одинаковой учётной записью, затем повтори проверку с другой учётной записью.
- `main` обновляется после тестов и подтверждения владельца.
